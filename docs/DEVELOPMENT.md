# 開發者說明（內部設計、需求對照、已知限制）

> 給想改程式或審查的人看。一般使用者請看專案首頁的 README。這份是從開發過程整理來的，部分描述（例如題數）可能比實際略舊，以程式與測試為準。

## 這個程式是給誰、做什麼用

**核心：一個大家會想點進去玩的「反直覺憲政題庫」。** 每一題都有一句聽起來很有道理的話，讓人自己試著判斷，答完才發現它和憲政規則相反——自己發現搞錯了，印象才深。

- **玩的人**：打開網站（或點別人傳的連結、或開一個 .html 檔），挑題目試試，不用登入。答完到「我的盲點」看自己哪裡和判準不同，可以記筆記。
- **出題的人（學者、利害關係人）**：到「作者工具」，**輸入條號或關鍵字查官方條文**（內建憲法、增修條文、行政程序法，原文取自全國法規資料庫，離線可查，**不需要任何 AI**），按「用這條出題」，條文原文、官方連結、定位、相關的憲法法庭裁判就自動帶進來；再回答三個問題（憲政體制的答案是什麼、一般人第一反應是什麼、屬於哪一種常見誤區），系統起一個題目**骨架**——情境、選項、正解都留給你，不會替你猜。檢查頁會用中文指出哪一欄沒填，並提醒常見的出題錯誤（範本文字沒改、正解特別長、每題都選「否」、引文和官方條文不一致…）。可以下載「審查用文件」（每題排成好讀的一頁、附條文原文與審查欄，可列印成 PDF）給專家看。這些題目只是**增加題庫的過程**。
- **分享給別人**（不需要伺服器、不需要帳號）：
  1. **傳連結**：題目壓縮在連結裡，對方點開就能考（題數少時適用，約 3 題以內；太長會提醒）。
  2. **傳單一檔案**：下載成一個 .html，對方連點兩下用瀏覽器開，**不用網路、不用安裝、不會對外連線**。
  3. **傳題庫檔**：作者工具下載的「題庫檔」，交給網站管理員，放進網站的題庫（作者不需要懂檔案格式）。

不收集任何人的作答；每個人的答案只留在自己的瀏覽器裡。

依 `civic-inquiry-spec-2026-10-17` 規格實作。V0.2 是最小互動版（FR-01～06、12）；**V0.3 加入探索與新聞搜尋代理**（FR-07、FR-08；AT-07、08、17）。
**V1.0 候選加入**（只做不需要帳號與伺服器的部分）：多題庫與英文譯本（FR-13）、離線閱讀 PWA（FR-14，可選）、靜態部署模式、效能量測、部署與維護手冊（見 [DEPLOYMENT.md](DEPLOYMENT.md)）、撤回指令。**作者帳號、雲端發布、雙審流程（FR-11）沒有做**。
**V0.4 加入作者工具**（FR-09、FR-10；AT-10、19 的自動化部分）：表單精靈、預覽、匯入匯出、版本差異與修訂，入口是 `#/author`。
**搜尋目前使用明示的「測試替身」，結果是假資料；沒有申請任何搜尋供應商，也沒有金鑰。**
這是教育原型：臺灣憲政題庫的法源只經初步比對，**尚未經過獨立的法律與教育專業審查**，畫面上一律標示為「教育原型」。

## 題目長什麼樣

每題一頁讀完：**標題（不洩漏結論）→ 情境（具體事件）→ 問題與選項**。不先問立場，也不問把握程度。答完看到：**憲政體制的答案 → 依據（條文原文＋官方連結）→ 解釋 → 為什麼直覺會出問題**，更多內容收在「再多看一點」。條文原文都逐字出自素材庫，測試會逐條比對。

## 素材庫（官方條文）怎麼更新

```bash
node scripts/build-corpus.mjs            # 重抓憲法、增修條文、行政程序法
node scripts/build-corpus.mjs A0010001   # 指定其他法規代碼（全國法規資料庫網址裡的 pcode）
```

結果存在 `src/data/corpus.json`。裁判（釋字、憲判）目前只內建 4 筆的連結與一句話說明，見 `src/authoring/corpus.ts`；**裁判全文沒有收進來**，以憲法法庭網站為準。

## 怎麼跑

需要 Node.js 20 以上。

```bash
npm install
npm run api        # 搜尋代理（測試替身）http://localhost:8787，另開一個終端機執行
npm run dev        # 開發伺服器 http://localhost:5173（會先驗證並發布內容；/api 轉給代理）
npm run build      # 驗證內容 → 型別檢查 → 正式建置（含 CSP）
npm run preview    # 以正式 bundle 預覽
npm test           # 單元測試（驗證器、判分、資格判斷、隔離）
npm run test:e2e   # 真 Chrome 端對端測試（會自己建置並起伺服器；用 CIVIC_FIXTURES=1 載入測試題庫）
npm run test:perf  # 效能量測：4 倍 CPU 節流、1.6 Mbps、150 ms，20 次冷啟動
npm run build:static   # 靜態部署版（沒有搜尋面板）
npm run build:pwa      # 離線閱讀版（註冊 Service Worker）
npm run withdraw -- 題目代號@版本 "理由"   # 撤回一題
```

端對端測試用本機已安裝的 Google Chrome（Playwright `channel: 'chrome'`），測的是**建置後的正式 bundle**，不是開發伺服器。

## 目錄

| 路徑 | 內容 |
|---|---|
| `content-src/*.quiz.json` | 題庫原稿（正式交換格式 1.0.0）。**審查標章不在這裡授予**，在 `status-overrides.json` |
| `scripts/publish-content.ts` | 發布：嚴格解析 → Schema → 語意驗證，全過才寫入 `public/content/`；產生 catalog 與 24 小時有效的 status |
| `src/core/` | 嚴格 JSON 解析、Schema 直譯器、語意驗證（REF/EDU/TIME/GOV/SEC/LANG）、Eligibility、Assessment、內容載入 |
| `src/session/` | 讀者 Attempt、記憶體 store、可選的 IndexedDB 儲存 |
| `src/explorer/` | 預審閱讀清單。**不得引用 `src/session`**，有測試把關 |
| `server/` | 搜尋代理：請求驗證、供應商轉接介面與測試替身、權利登記、全站配額、降級；`index.ts` 是 Node 參考部署 |
| `src/search/` | 前後端共用的搜尋契約（請求嚴格驗證，拒絕任何多餘欄位） |
| `src/authoring/` | 作者核心：草稿模型（JSON 路徑讀寫）、匯入匯出、版本差異與修訂、本機草稿儲存 |
| `src/ui/author/` | 表單精靈畫面與預覽 |
| `src/ui/` | React 畫面與安全 Markdown 渲染 |
| `tests/` | 單元測試；`tests/e2e/` 為瀏覽器測試 |

## 需求對照

| 需求 | 做法 | 自動化驗證 |
|---|---|---|
| FR-01 無帳號 | 公開連結直接開，沒有登入／註冊 | AT-01 |
| FR-02 直覺、知識、信心、揭曉分開 | 三階段；價值題永不計分；揭曉後首次答案鎖定 | AT-02 |
| FR-03 single／multiple／reflection | `judge()` 純函式；多選集合完全相等才對；不知道、略過、反思不入分母 | AT-03（單元） |
| FR-04 分層解釋與原始證據 | 核心差異 → 機制／理由／替代／限制 → 來源與定位 | 人工讀過 |
| FR-05 有效性與撤回 | 可信狀態目錄＋雜湊；離線、過期、撤回、目錄缺失一律不當現行題 | AT-05（含注入時鐘邊界） |
| FR-06 本機答題與可選儲存 | 預設只在記憶體；選擇才寫 IndexedDB，30 天到期；一鍵清除 | AT-06 |
| FR-12 討論與筆記 | 引導問題、本機筆記、不含作答的回報文字（複製／下載） | AT-12 |
| FR-07 探索入口 | 題內探索：類別、來源類型、語言、日期起訖（含最近一年）、只看已審查、排序；日期未知與語言未知的結果在篩選時排除並明說 | AT-07 |
| FR-08 混合搜尋與降級 | 讀者按「搜尋」才送出；逾時 8 秒、429、5xx、未啟用、額度用完、無結果都有可操作的訊息，預審清單與測驗不受影響 | AT-08（含降級各情況） |
| FR-09 作者工具 | 五步驟精靈（題庫資訊、來源、題目、檢查與預覽、版本與匯出入）；欄位直接對應驗證錯誤；預覽用和讀者相同的畫面與引擎，缺正解時顯示「無法判定」；匯出入單一 .quiz.json（鍵排序、LF、兩格縮排，往返位元組相同） | 單元＋E2E（用畫面做出物理題庫） |
| FR-10 版本與審查分離 | 從已發布版本建立修訂 → 差異分「需重新審查」與「文字修訂」→ 完成修訂只對有變動的題升版並重置審查、記錄原因與被取代版本；匯入檔自稱 reviewed 一律只是作者聲明；同版本內容不同回報 VERSION_COLLISION，不覆蓋 | AT-10、AT-19 |
| 搜尋隔離（AT-17） | 答對、答錯、沒作答三種情況送出的請求完全相同；供應商轉接器只收得到查詢字串、語言、地區、日期 | AT-17 |

## 已知限制與誠實聲明

- **效能（AT-16）只量了桌機 Chrome 加節流**：LCP p75 約 1.7 秒、CLS 最大約 0.044、單題互動 p95 約 17 ms、JS 壓縮後約 99 KiB（都在門檻內）。這不是中階 Android 實機，也不是真實使用者數據，實機與 iPhone Safari 仍需另外量。
- 多題庫：第 2 份以後的題庫作答只存在記憶體（不支援本機儲存）。譯本要求同題庫代號、不同語系；缺譯文時只引導讀原文，不做機器翻譯；**介面文字目前只有繁體中文**（介面語系與題庫語系已分開，但沒有翻譯介面）。
- PWA：離線只能歷史閱讀；不快取 /api 與 status.json。沒在行動裝置實機測過安裝流程。
- Dockerfile 與「備份還原演練」都沒有實際做過，見 DEPLOYMENT.md。
- **AT-09（5 位無程式背景的作者、45 分鐘內建立 2 題）沒有做**：那是真人任務測試。我只用 Playwright 照畫面操作做出一份物理題庫，證明流程走得通，不能證明「非工程作者能獨立完成」。需要找人試，並記錄卡關點（R07）。
- 作者工具**沒有**：審查報告編輯與雙審流程（需要作者帳號與伺服器，規格排在 V1.0）、雲端發布（只提供「下載發布包」，有說明怎麼交給部署管理員）、作者帳號。審查標章仍然只能由 `status-overrides.json` 授予。
- 草稿存在這台裝置的 IndexedDB（獨立於讀者資料）；清除瀏覽器資料就會消失，所以有「下載草稿備份」。
- 版本差異以欄位為單位，選項順序調整會顯示為多筆修改。
- **搜尋是測試替身**：AT-18（30 組真實查詢、切題率、語言符合率）**完全沒做**，因為沒有真實供應商。真正啟用前必須：取得供應商方案與條款確認（填 `server/rights.ts` 的權利登記）、寫一個供應商轉接器、做 30 組試查。在那之前不能宣稱提供可靠的即時新聞搜尋。
- 配額是單一程序內的計數器；若部署成多個 Serverless 實例，需改用共享的原子計數器，否則無法全站封頂。每 IP 限流、預算 80% 通知管理員的通道、每週連結檢查排程都**還沒做**。
- 搜尋沒有分頁（回傳 `nextCursor: null`）。
- **只自動化驗證了部分驗收**。AT-15（無障礙）目前是 axe 自動掃描（含深色模式）、320 px 不橫向捲動、44 px 點選區、鍵盤走完一題；**尚未做 NVDA＋Chrome、VoiceOver＋Safari 的人工走查**，也沒有 400% 縮放的實測（只測了 320 px 寬）。
- **AT-16（效能）沒有量測**：只知道正式 bundle 的 JS 約 280 kB（gzip 約 88 kB，低於 200 KiB 目標）。LCP／CLS／互動延遲都需要在中階 Android 實機量，尚未做。
- 只測了 Windows 上的 Chrome。Android Chrome、iPhone Safari、Edge 都沒測。
- 離線：目前**沒有** Service Worker／PWA（規格排在 V1.0）。開著頁面後斷網，題目會降為歷史閱讀；若是一開始就離線，會顯示「題庫無法使用」。
- 狀態目錄（`status.json`）由 `npm run content` 產生，**24 小時後就過期**，過期後所有題都會變成歷史閱讀——這是規格的設計，不是 bug。部署時需要排程重新發布，或接上真正的狀態服務。
- 沒有任何已審查標章：`status-overrides.json` 是空的。審查報告流程、發布管理員、作者工具（V0.4）都還沒做。
- 規格在「30 天儲存」上有一句模糊的敘述（「以 lastSavedAt 檢查，不以修改答案刷新無限保留」）。我採用：**期限從讀者選擇儲存的那一刻起算，之後改答案或寫筆記都不會延長**。若你希望每次寫入都重新計時，請告訴我。
- 「想看更多？用關鍵詞自己搜尋」的外部連結指向 DuckDuckGo（我選的預設）；按下後離開本站。
- 「換一個情境試試」（EDUCATIONAL_DESIGN §4）沒做，因為需要另寫情境題。
- 法源：全國法規資料庫的整編截止日可能早於查閱日；發布前須由領域審查者補查。

## 兩個值得知道的設計決定

1. **Schema 驗證不用 Ajv 於執行期**。Ajv 會用 `new Function` 動態產生程式，違反規格要求的 CSP（不得 `unsafe-eval`）——一開始用 Ajv，正式版直接白屏，端對端測試才發現。改成自寫的小型直譯器（`src/core/schemaCheck.ts`），並用 Ajv 在測試裡對 3000 個隨機突變做交叉比對，確保兩者判斷一致。
2. **預設不在裝置上留下任何東西**：沒選儲存就不會建立 IndexedDB（連空資料庫都不會）；清除時整個資料庫刪掉。
