# 實機驗收：效能量測與無障礙人工走查

這份文件教你一步一步做兩件事：**在真的手機上量速度**，以及**用螢幕閱讀器（NVDA、VoiceOver）走完一遍流程**。
自動化測試做不到這兩件事。做完請把結果貼回給我，我會整理進驗收紀錄。

預估時間：準備 20 分鐘、效能量測 30 分鐘、NVDA 30 分鐘、VoiceOver 30 分鐘。三個部分可以分開做。

---

## 第 0 步：先把網站放到手機打得開的地方

**為什麼這步不能省：** 網站需要「安全連線」（網址以 https 開頭，或是 localhost）才能運作。直接用區域網路的 `http://192.168.…` 開，手機上會是一片空白。

你有兩種做法，挑一種：

### 做法 A（最簡單，iPhone 和 Android 都適用）：暫時放到免費的靜態網站空間

前提：你願意把這個「教育原型」公開放在一個臨時網址上。內容只有題目和法源連結，沒有任何個人資料。

1. 在電腦上，開終端機，進到專案資料夾：
   ```bash
   cd D:\claude\civic-inquiry
   ```
2. 建置靜態版（會自動檢查內容）：
   ```bash
   npm run build:static
   ```
   成功的話，會多出一個 `dist-static` 資料夾。
3. 打開 <https://app.netlify.com/drop>，把 `dist-static` 資料夾整個拖進去。它會給你一個 `https://….netlify.app` 的網址，這就是你的測試網址。（需要免費註冊；我不會、也不能替你註冊或登入。）
4. 在手機上打開那個網址，確認看得到「臺灣民主與憲政制度：12題教育原型」。

**重要：** 題目的「有效狀態」只有 24 小時。**請在建置後同一天內做完測試**；隔天所有題目會變成「歷史閱讀」，那是正常的設計，不是壞掉。

### 做法 B（只有 Android，需要 USB 線）

1. 手機：設定 → 關於手機 → 連點「版本號碼」7 次，開啟開發人員選項，再開「USB 偵錯」。
2. 電腦先裝好 Android 的 `adb`，手機用 USB 連上電腦並允許偵錯。
3. 電腦開兩個終端機：
   ```bash
   npm run build:static
   npx vite preview --outDir dist-static --port 4180
   ```
   ```bash
   adb reverse tcp:4180 tcp:4180
   ```
4. 手機的 Chrome 打開 `http://localhost:4180`。（localhost 算安全連線，所以可以用。）

> 如果你卡在這一步，把畫面或錯誤訊息貼給我，我陪你處理。

## 第一部分：真機效能量測

**目標：** 在中階 Android 手機上，冷啟動 20 次，LCP（最大內容出現的時間）的第 75 百分位要 ≤ 2.5 秒；版面跳動 CLS ≤ 0.1；互動延遲 p95 ≤ 100 毫秒。

> 名詞：LCP＝畫面上最大的那塊內容出現要多久；CLS＝畫面有沒有突然跳動；「冷啟動」＝完全沒有快取、像第一次來。

### 準備

- 用**中階或更舊的 Android 手機**量（越舊越有參考價值）。iPhone 另外量一輪也歡迎，分開記錄。
- 用 Chrome，**不要**開「資料節省」。
- 手機盡量不要在充電、不要同時開很多程式。
- 記下你用的是 **Wi-Fi 還是行動網路**。規格的條件是下行約 1.6 Mbps；用 Wi-Fi 量到的數字會比較樂觀，請一定寫明。

### 每一次要做的事（做 20 次）

1. 開一個**新的無痕分頁**（無痕分頁沒有快取，等於冷啟動）。
2. 網址列輸入你的測試網址，後面加上 `?perf=1`，例如：
   `https://你的網址.netlify.app/?perf=1`
3. 等 5 秒。畫面右下角會出現一個黑色小框，上面有 **LCP** 和 **CLS** 的數字。
4. 把 **LCP（毫秒）** 和 **CLS** 抄在下面的表格。
5. 關掉這個無痕分頁，重來。

小黑框只在你網址加了 `?perf=1` 才會出現，**不會上傳任何資料**。

### 量互動延遲（做一次就好）

1. 網址換成 `你的網址/?perf=1#/quiz/1`。
2. 照正常流程點：選一個選項 → 下一步 → 選答案 → 確認答案 → 選信心 → 看解釋。重複做幾題，**總共至少點 15 次以上**。
3. 看小黑框的「互動延遲 p95」。按「複製結果」，貼給我。

### 要貼給我的格式

```
手機型號與 Android 版本：
Chrome 版本（設定 → 關於 Chrome）：
網路：Wi-Fi / 行動網路（哪一家、幾格訊號）
測試日期與時間：

20 次冷啟動：
 1. LCP=____ ms  CLS=____
 2. LCP=____ ms  CLS=____
 …（做到第 20 次）

互動延遲 p95：____ ms（總共 ____ 次互動）
覺得卡的地方（有的話）：
```

只要貼數字，我來算第 75 百分位和判斷有沒有過關。如果你覺得 20 次太多，至少做 10 次，我會在紀錄裡註明「次數不足」。

## 第二部分：NVDA ＋ Chrome（Windows 電腦）

**目標：** 只用鍵盤和螢幕閱讀器，能完整走完一題，而且每一步都聽得懂、不會被卡住。

### 準備

1. 下載 NVDA（免費）：<https://www.nvaccess.org/download/>。安裝時選「安裝到這台電腦」或「建立可攜式版本」都可以。（下載與安裝由你自己操作。）
2. 啟動 NVDA（Ctrl＋Alt＋N）。它會開始念出畫面上的字。**把電腦音量打開。**
3. 用 Chrome 打開你的測試網址。
4. 想暫時讓它安靜：按一下 Ctrl。想關掉 NVDA：按 Insert＋Q。

### 這次**不要用滑鼠**。只用這些鍵

| 按鍵 | 作用 |
|---|---|
| Tab / Shift＋Tab | 往下／往上跳到下一個可操作的東西 |
| 空白鍵 | 勾選選項、按按鈕 |
| Enter | 按連結、按按鈕 |
| H | 跳到下一個標題 |
| 方向鍵上下 | 在選項之間移動（選項是單選時） |

### 要走的流程，邊走邊對照「檢查項目」

1. 打開首頁。**檢查：** NVDA 有沒有念出網頁標題與主標題？
2. 按 Tab，第一個停的地方是不是「跳到主要內容」連結？按 Enter 會不會跳到內容？
3. 按「開始」進到第 1 題。**檢查：** 有沒有念出「第 1 題／共 12 題」「情境」？
4. 第一步（你希望如何）：用方向鍵或 Tab 選一個選項，按空白鍵。**檢查：** 有念出選項名稱和「已選取」嗎？問題本身（題幹）有被念出來嗎？
5. 按「下一步」→ 第二步知識題。選答案 → 「確認答案」。
6. 信心頁：選一個 → 「確認，看解釋」。
7. **最重要的一步：** 看解釋的那一刻。**檢查：**
   - NVDA 是不是**只念一次**結果（例如「你的答案與此版本的判準一致」），不是把整頁念一遍？
   - 焦點是不是跑到結果標題？接著按 Tab 是不是從結果往下走？
8. 按 H 一路跳標題：**檢查：** 有沒有「核心差異」「想看更深入的說明」「探索」「討論與反思」這些標題，順序合理嗎？
9. 把「機制」這類可展開的區塊用 Enter 或空白鍵打開／關閉。**檢查：** 有念出「已展開／已收合」嗎？
10. 按「回報內容問題」→ 輸入文字。**檢查：** 輸入框有被念出標籤嗎？
11. 到「探索」：改「資料類別」下拉選單，按「搜尋」。**檢查：** 搜尋完，有念出「共 N 筆」之類的結果通知嗎？
12. 外部連結：**檢查：** NVDA 有念出「另開新視窗，離開本站」嗎？
13. 到「隱私設定」，按「清除所有進度與筆記」。**檢查：** 有念出「已清除」嗎？
14. 整個流程中：**有沒有任何一個地方，鍵盤按 Tab 會卡住出不來？**（鍵盤陷阱）

### 順便試作者工具（選做）

打開 `網址/#/author` → 「開始建立」→ 逐步填欄位。**檢查：** 每個欄位都有被念出名稱嗎？故意漏填後，錯誤訊息有被念出來嗎？

### 要貼給我的格式

```
NVDA 版本：
Chrome 版本：
Windows 版本：

流程 1～14：每一步寫「正常」或「有問題：發生了什麼、NVDA 念了什麼」
卡住或聽不懂的地方（越具體越好，例如「第 7 步念了兩次結果」）：
```

不用判斷「這算不算違規」，只要老實寫你聽到什麼、卡在哪。

## 第三部分：VoiceOver ＋ Safari（iPhone）

**目標：** 在 iPhone 上，用 VoiceOver 走完同樣的流程。

### 準備

1. iPhone：設定 → 輔助使用 → VoiceOver → 開啟。（第一次開會有教學；也可以設定「輔助使用快速鍵」，之後連按側邊鍵三下開關。）
2. 開啟後，**手指的操作會變**：
   - 點一下＝選取並念出該項目
   - **連點兩下**＝按下去（啟用）
   - 向右滑一下＝下一個項目；向左滑一下＝上一個項目
   - 兩指向上滑＝從頭念到尾（先別用）
3. 用 **Safari** 打開測試網址。
4. 不想被打擾時：三指點一下可以暫時把聲音關掉（再點一下恢復）。

### 流程（和 NVDA 一樣，改成手機動作）

1. 首頁：向右滑，逐項聽。**檢查：** 標題、「開始」按鈕都念得出來？
2. 連點兩下「開始」。
3. 在選項上向右滑，**檢查：** 每個選項都念出「單選按鈕」和「已選取／未選取」？連點兩下選取。
4. 一路到看解釋。**檢查（最重要）：** 結果是不是**只念一次**？
5. 往下滑聽「核心差異」「想看更深入的說明」。展開／收合區塊：**檢查：** 有念出「已展開」嗎？
6. 探索區：搜尋後有沒有念出結果筆數？
7. **放大測試：** 設定 → 輔助使用 → 顯示與文字大小 → 更大的文字 → 開到最大。回到網站。**檢查：** 有沒有橫向捲動？按鈕有沒有被切掉？
8. **橫向／直向：** 把手機轉橫再轉直，內容有沒有壞掉？

### 要貼給我的格式

```
iPhone 型號與 iOS 版本：
Safari 版本（若看得到）：

流程 1～8：每一步寫「正常」或「有問題：發生了什麼、VoiceOver 念了什麼」
```

1. 算出效能的第 75 百分位與互動延遲，標出有沒有過關；

3. 更新驗收紀錄，**明確寫出哪些是實機測過、哪些還沒測**。
